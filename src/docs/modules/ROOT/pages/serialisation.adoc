= JSON Serialisation
Paul Snow
:description: toJson/fromJson support on every hr_zones value type, using dart:convert only — no code generation, no build step.

Every public value type in `hr_zones` has a `toJson()` method and a matching `fromJson` factory constructor, so results can be persisted, cached, or sent over the wire without hand-rolled conversion code.

== Design

* Serialisation uses `dart:convert` only — there is no code generation and no build step. `hr_zones` gains zero extra runtime dependencies from this feature.
* Enums are serialised by their `name` (a string), not by ordinal, so adding new enum values in future releases won't silently corrupt values encoded by older versions. This applies to `MaxHrFormula`, `ZoneMethod`, and `ZoneReliability`.
* `Duration` values are serialised as integer microseconds. For example, `HrReading.elapsed` becomes the JSON key `elapsedMicroseconds`.
* Null optional fields are omitted from the JSON map rather than encoded as `null`.
* Every type is round-trip-stable: `fromJson(x.toJson()) == x`.

== Types with toJson/fromJson

[cols="1,3", options="header"]
|===
|Type |Notes

|`HealthProfile` |Input model; optional fields are omitted when `null`.
|`CustomZoneBoundary` |Explicit zone lower bounds and optional labels.
|`ZoneConfiguration` |Result of `calculateZones`; embeds a `List<CalculatedZone>` and the `ZoneMethod`/`ZoneReliability` enums.
|`CalculatedZone` |One zone within a `ZoneConfiguration`.
|`HrReading` |`elapsed` becomes `elapsedMicroseconds`.
|`TimeInZoneSummary` |Result of `calculateTimeInZones`; embeds a `List<ZoneDuration>`.
|`ZoneDuration` |Pairs a `CalculatedZone` with a `Duration`, encoded as microseconds.
|`BanisterCoefficients` |The `a`/`b` weighting pair.
|===

== Example: round-tripping a ZoneConfiguration

[source,dart]
----
import 'dart:convert';
import 'package:hr_zones/hr_zones.dart';

final profile = HealthProfile(age: 40, restingHr: 55);
final config = calculateZones(profile)!;

// Encode to a JSON string…
final text = jsonEncode(config.toJson());

// …and decode it back to an identical value.
final restored = ZoneConfiguration.fromJson(jsonDecode(text));
assert(restored == config);
----

== Example: round-tripping a list of readings

`toJson`/`fromJson` work on individual values, so collections are handled with the usual `map` calls:

[source,dart]
----
final readings = [
  HrReading(bpm: 120, elapsed: Duration.zero),
  HrReading(bpm: 140, elapsed: Duration(minutes: 20)),
];

final text = jsonEncode(readings.map((r) => r.toJson()).toList());

final decoded = jsonDecode(text) as List;
final restored = decoded
    .map((m) => HrReading.fromJson(m as Map<String, dynamic>))
    .toList();
assert(restored.length == readings.length);
----

NOTE: `fromJson` expects a `Map<String, dynamic>`, which is exactly what `jsonDecode` produces for a JSON object. When decoding a JSON array of objects, decode the array first and then call `fromJson` on each element, as shown above.

== Omitted null fields

Optional fields that are `null` are left out of the encoded map rather than written as `"field": null`. This keeps encoded payloads compact, and `fromJson` treats a missing key the same as an explicit `null` when decoding it back.

For example, a `HealthProfile` built with only `age` and `restingHr` set will not contain `measuredMaxHr`, `clinicianMaxHr`, or `lactateThresholdHr` keys at all in its JSON form.
