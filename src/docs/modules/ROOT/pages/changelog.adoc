== 0.1.0 (2026-07-12)

This release contains breaking changes.
The minor version is bumped (rather than the patch version) to signal that call sites need updating; see the migration note under *Changes*.

=== New features

JSON serialisation::
`toJson()` and a matching `fromJson` factory are now available on every public value type — `HealthProfile`, `CustomZoneBoundary`, `ZoneConfiguration`, `CalculatedZone`, `HrReading`, `TimeInZoneSummary`, `ZoneDuration`, and `BanisterCoefficients`.
Uses only `dart:convert` — no code generation, no build step, zero runtime dependencies — and every type round-trips (`fromJson(x.toJson()) == x`).
Backed by new value `==`/`hashCode` on `HealthProfile`, `ZoneConfiguration`, `TimeInZoneSummary`, `ZoneDuration`, and `BanisterCoefficients` (previously identity-only).
See xref:serialisation.adoc[JSON Serialisation] for details.

Recovery-sample flag::
`HrReading.isRecoverySample`, when set on the final reading, tells `calculateTimeInZones` to exclude the preceding cooldown interval from the per-zone totals and populate `recoveryHrDrop` deterministically — avoiding a late sensor dropout being misread as a recovery measurement.

Below-zone-1 duration::
`TimeInZoneSummary.belowZone1Duration` now surfaces the time whose starting reading fell below zone 1, which was previously discarded without being reported.

=== Changes

Breaking: HealthProfile and CustomZoneBoundary validate at construction::
Both constructors now validate their inputs and are therefore no longer `const`.
Call sites written as `const HealthProfile(...)` or `const CustomZoneBoundary(...)` must drop the `const` keyword (use `final` for the local variable).
+
They throw `ArgumentError` when: any supplied `age`, `restingHr`, `measuredMaxHr`, `clinicianMaxHr`, or `lactateThresholdHr` is not positive; `restingHr` is at or above a supplied `measuredMaxHr` or `lactateThresholdHr`; `CustomZoneBoundary` lower bounds are not positive or not strictly increasing; or `CustomZoneBoundary.labels` is supplied with a length other than five.
+
Validation moved into the constructors because a profile is typically built from user input at runtime, where `assert` is stripped in release AOT builds — failing at construction also names the offending field, rather than surfacing much later as nonsensical zones.
+
Two checks deliberately stay outside the constructor. `restingHr` is still checked against an _age-estimated_ max by `calculateZones`, because a measured max can outrank the age estimate. `restingHr` is *not* checked against `clinicianMaxHr` at all — a conservative prescribed cap may legitimately sit at or below resting HR, and `calculateZones` degrades to flat percentage bands for that case.

Breaking: raised the minimum Dart SDK to ^3.8.0::
Was `^3.4.0`. Matches the `lints: ^6.1.0` dev-dependency, which requires SDK `>=3.8.0`. The CI matrix now tests `3.8.0` and `stable`.

Breaking: calculateZones rejects an inconsistent resting/age-estimated max::
Throws `ArgumentError` when `restingHr` is at or above the resolved max HR, instead of silently falling through to a percentage method and returning nonsensical zones.
Where the max is supplied directly the check now happens earlier, in the `HealthProfile` constructor; `calculateZones` retains the check for the age-estimated max, which it alone can resolve.

Clinician cap personalised with Karvonen::
`calculateZones` now applies the HRR/Karvonen formula to the clinician-cap method when a `restingHr` is available, so the lower zones sit above resting HR instead of a flat percentage that could fall below it.
`method` remains `ZoneMethod.clinicianCap` and reliability remains `high`.

calculateBanisterTrimp resolves more max HR sources::
Now resolves the maximum heart rate as `clinicianMaxHr ?? measuredMaxHr ?? estimatedMaxHr`, so clinician-capped profiles get a training-load score instead of `null`.

Override lists and custom bounds validate their length::
The `bands`/`labels`/`effortLabels`/`descriptiveLabels`/`colors` overrides passed to `calculateZones` now throw `ArgumentError` when their length is not exactly five (previously an `assert`, stripped in release builds).
`CustomZoneBoundary` lower bounds that are not strictly increasing, and `labels` of a length other than five, now throw `ArgumentError` from the constructor instead of silently building inverted zones or crashing with a bare `RangeError`.

Custom zone label format::
Custom zone `labels` are now combined into the UI label as `'Zone N – <label>'` (previously the bare label replaced it), and an explicit `labels:` argument to `calculateZones` now takes precedence over `CustomZoneBoundary.labels`.

Unmodifiable result lists::
`ZoneConfiguration.zones` and `TimeInZoneSummary.zoneDurations` are now unmodifiable lists.

=== Documentation

* Corrected the package description, which described five calculation methods rather than the six now supported — the LTHR/Friel method was missing from the list.
* Corrected the `CalculatedZone.upperPercent` contract to note that the `ZoneMethod.lthrFriel` top zone can exceed `1.0` (default Friel zone 5 runs to 110% of LTHR).
* Corrected stale worked examples and expected outputs (Edwards TRIMP, the getting-started version pin and output, Åstrand / Miller–Faulkner formula values, and method `reason` strings).
* Documented `ZoneConfiguration.maxHr` semantics for custom zones, the dual interpretation of the `bands` parameter (percent-of-max vs percent-of-LTHR), and the input contract on `HealthProfile` and `MaxHrFormula.apply`.

== 0.0.3 (2026-04-17)

A packaging-only release — no library or API changes.

== 0.0.2 (2026-04-17)

=== New features

Six-method priority chain::
The priority chain grows to six methods with the addition of the LTHR/Friel method.
Position 3 in the chain: after clinician cap, before HRR/Karvonen.
When a measured lactate threshold is available it provides a more meaningful anchor than an estimated max.

LTHR / Friel zones (`ZoneMethod.lthrFriel`)::
`HealthProfile` gains `lactateThresholdHr` (and matching `copyWith` / `clearLactateThresholdHr` support).
Zones are computed using Joe Friel's five-zone bands expressed as percentages of LTHR.
`ZoneConfiguration.maxHr` holds the LTHR anchor when this method is active.

Three additional max-HR formulas::
`MaxHrFormula` adds `gellish2007` (`207 − 0.7 × age`), `astrand` (`216.6 − 0.84 × age`), and `millerFaulkner` (`217 − 0.85 × age`).
The enum now has six values.
See xref:max-hr-formulas.adoc[Max HR Formulas] for citations and sample calculations.

Training-load functions::
New `calculateEdwardsTrimp(TimeInZoneSummary)` and `calculateBanisterTrimp(List<HrReading>, HealthProfile, {coefficients})`.
Also adds `BanisterCoefficients` with `male()` (a=0.64, b=1.92) and `female()` (a=0.86, b=1.67) named constructors.
See xref:training-load.adoc[Training Load (TRIMP)] for details.

=== Changes

Pubspec description shortened to satisfy pub.dev's 60–180 character limit and achieve full marks on the "Follow Dart file conventions" check.

=== Fixes

Removed the `document_ignores` lint rule from `analysis_options.yaml` so the analyser passes on the Dart 3.4.0 SDK floor (the rule was only added in Dart 3.5).

== 0.0.1 (2026-04-17)

Initial release.

=== Added

HealthProfile input model::
Accepts `age`, `restingHr`, `measuredMaxHr`, `clinicianMaxHr`, `betaBlocker`, `heartCondition`, `customZones`, and `maxHrFormula`.
Provides `estimatedMaxHr`, `isCautionMode`, and `copyWith`.

MaxHrFormula enum (three values)::
`tanaka` (default), `fox220`, and `nes`.
Extension `MaxHrFormulaApply` adds `.apply(age)` and `.displayName`.

Five-method priority chain::
`calculateZones(HealthProfile, {bands, labels, effortLabels, descriptiveLabels, colors})` returning `ZoneConfiguration?`.
Priority order: custom → clinicianCap → hrrKarvonen → percentOfMeasuredMax → percentOfEstimatedMax.

ZoneConfiguration and CalculatedZone::
Result type with `zones`, `method`, `reliability`, `maxHr`, and `reason`.
Each `CalculatedZone` exposes `zoneNumber`, `label`, `effortLabel`, `descriptiveLabel`, `displayLabel`, `lowerBound`, `upperBound`, `color`, `lowerPercent`, `upperPercent`, and `containsBpm`.

Caution mode::
`betaBlocker` and `heartCondition` flags downgrade reliability to `low` unless a clinician cap is present.

Real-time zone lookup::
`currentZoneFromConfig(int bpm, ZoneConfiguration)`.

Time-in-zone analysis::
`HrReading` value type; `calculateTimeInZones` returning `TimeInZoneSummary`; `ZoneDuration`; `ReadingCadence.cooldownGap` constant; cooldown-gated `recoveryHrDrop`.

Full test suite::
123 tests covering the zone calculator, health profile, time-in-zone calculator, and end-to-end integration pipeline.

CI and publish workflows::
GitHub Actions CI runs `dart analyze --fatal-infos` and `dart test` on Dart SDK versions 3.4.0, 3.6.0, and `stable`.
Publish workflow uses OIDC for automated publishing to pub.dev on `vX.Y.Z` tag push.
